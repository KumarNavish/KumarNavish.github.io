# CasePath release governance

## Release identity

`release.json` is the `casepath.release-contract/2.2.0` product contract. A
release is aligned only when the
frontend, API, and QA services report the same `release_id` and the same
non-`unknown` source commit. Frontend, API, pipeline, and QA semantic versions
are independent compatibility markers and are not required to be numerically
equal.

`release.json` deliberately embeds neither a source commit nor a production
runtime verdict. Those facts do not exist until a particular deployment and QA
execution exist; writing them back into source after QA would create a new
commit that the recorded evidence did not test. The tracked contract therefore
defines immutable acceptance criteria, while the dynamic `report.json` and
`evidence-manifest.json` pair is the verdict authority for one deployed commit.

`source-manifest.json` is generated by `casepath/tools/casepath_release.py`.
It inventories every tracked or non-ignored pending file in `casepath/`,
`casepath-api/`, and `casepath-qa/`, plus `render.yaml`, excluding only its own
output and build artifacts. It also binds the browser gates and model-visible
artifact bytes. An unavailable `RENDER_GIT_COMMIT` is recorded as `unknown`;
that state is truthful but release-blocking for cross-service alignment.

The static-site build runs `casepath/tools/build_deployment_identity.py` and
writes the ignored build output `casepath/deployment.json`. The output binds the
release ID and frontend version to `RENDER_GIT_COMMIT` without embedding a
self-referential commit in `release.json`. Local generation deterministically
uses `source_commit: unknown` and `alignment_eligible: false`; the Render build
uses `--require-known-commit` and fails if the platform commit is absent or not
a 40-character hexadecimal SHA.

## Artifact boundary

The application shell discloses that the claims are generated research data.
The evaluated documents and images do not repeat that disclosure because it
would leak construction provenance to a model or reviewer. The release tool
scans raw bytes, PDF text and metadata, email headers and bodies, and image
metadata for construction markers. Passing this mechanical scan is not a claim
that an independent reviewer found the artifacts realistic or blind-safe.

Artifact generation uses a fixed `SOURCE_DATE_EPOCH`, explicit document dates,
project-owned source images, metadata-stripping JPEG conversion, and a complete
hash manifest. Build scripts must never rewrite tracked Python source.

Scenario dates are bounded by the release contract. The flagship claim was
received on 1 August 2026, the unseen later-claim photograph is dated 8 August,
the later claim was received on 10 August, and this release is dated 11 August.
The release verifier enforces that ordering so evaluated evidence cannot
post-date the release.

## Agentic runtime contract

The production target is the
`nemotron_langgraph_multi_agent_hybrid_guarded` runtime profile. It uses
LangChain 1.3.14, LangGraph 1.2.9, and `langchain-openrouter` 0.2.7 with the
exact requested Nemotron model through OpenRouter. The dependency lock was
resolved and checked on CPython 3.13.9 and contains the complete application,
agent-framework, and build/test dependency set; Render installs the lock, not
an unconstrained framework range.

The LangGraph state graph declares six model-backed roles:

1. `canonical_facts` — guarded canonical facts;
2. `orchestrator_plan` — the Nemotron orchestration plan;
3. `document_source_integrity` — document and source-integrity proposals;
4. `process_decision_mapping` — process-decision proposals;
5. `evidence_checklist` — evidence and checklist proposals; and
6. `final_claim_brief_audit` — final-brief audit proposals.

The source-integrity and process-mapping specialists form one parallel branch.
Dynamic acceptance consumes the backend's authoritative `execution_topology`:
the deterministic application owns the compiled LangGraph, the two parallel
specialists depend on `orchestrator_plan`, and the evidence and final-brief
agents depend on their preceding deterministic gates. A duplicate top-level
parallel-group summary is not topology evidence.
Three explicitly non-model gates then retain deterministic safety authority:
`deterministic_process_gate`, `deterministic_evidence_gate`, and
`whole_playbook_gate`. A rejected proposal may be replaced by a deterministic
contract value, but the fallback must be disclosed and cannot be presented as
the agent's contribution.

Hosted LangSmith tracing is not an evidence surface. `external_tracing`, prompt
storage, and raw-output storage are all false in the release contract, and the
API Blueprint sets `LANGSMITH_TRACING=false`. The only durable model audit
surface is the sanitized application ledger: no prompt, raw response,
credential, or private validator reference may be retained.

## Model-validation boundary

Model truth is scoped by execution surface. Deterministic artifact generation
has passed in `deterministic_reference` mode with exactly zero model calls and
is not model-backed. This says nothing about production runtime acceptance.

The source contract carries no `pending` or `passed` production-runtime field
and makes no current model-acceptance claim. Runtime acceptance requires
`openrouter_nemotron`, the exact requested model
`nvidia/nemotron-3-ultra-550b-a55b`, the exact guarded LangGraph runtime above,
and one cold orchestration bound to all six required model roles. Every role
must have a distinct application call ID and provider response ID, positive
actual cost and prompt/completion/total token counts, a positive accepted
contribution, and more accepted than rejected proposals. The records must share
one orchestration ID, preserve the canonical-to-orchestrator-to-specialist
parent/delegation chain, and bind sanitized input/output artifact hashes. All
three deterministic gates must pass, and the exact guarded-fallback count must
be disclosed. Canonical source-reference projection IDs and counts must be
bound identically across the run audit and sanitized ledger. A paid provider
response, a cache replay, or a weak/unbound role
record does not satisfy that gate.

The source repair does not retry or bypass LangChain. The shared
`ChatOpenRouter` client facade still delegates exactly one SDK request. It
catches only `ResponseValidationError`, accepts only a bounded HTTP 200 JSON
completion envelope containing one assistant string choice, projects only the
identity/finish/usage fields CasePath consumes, and then resumes LangChain's
native strict structured-output parser. Invalid envelopes raise the constant
`provider_response_envelope` invariant outside the SDK exception scope; raw
response bodies are neither logged nor persisted. Current acceptance still
requires a new same-commit cold production journey with all six bound calls and
three passed deterministic gates.

Known aggregate provider charges for attempts 1, 2, 4, 5, and 6 remain USD
0.0528110; attempts 3 and 7 are unknown and excluded rather than treated as
zero. Attempt 7's USD 0.027645 reservation is not included. The responses
remain failed-attempt history, not successful application evidence. No raw
prompt, raw output, credential, or private reference is retained, and no
attempt is accepted model-backed release evidence.

The seven records above are listed under `historical_model_validation` with
`scope: failed_closed_history_only`; they can never establish current runtime
acceptance. No passing dynamic QA artifact pair has been verified as part of
this source edit, so current production model acceptance remains unestablished.

After a successful production journey, there is no source promotion commit.
The QA output directory itself is the atomic evidence unit:

- `report.json` must say `passed`, contain zero failures, bind the release ID,
  and show the frontend, API, and QA on one non-`unknown` 40-hex source commit;
- `evidence-manifest.json` must use
  `casepath.qa-evidence-manifest/1.0.0`, repeat that release and commit, bind the
  exact QA gate and runtime, and hash every retained JSON, screenshot, and
  video artifact; and
- the report must hash-bind that exact manifest. The retained flagship run and
  cold model ledger must prove all six distinct paid Nemotron calls, positive
  usage and actual cost, strict accepted majorities, parent/delegation lineage,
  guarded-fallback disclosure, and all three passed deterministic gates. Each
  accepted-artifact hash is recomputed from the retained float-free DTO: the
  process graph, evidence checklist, and final claim brief respectively; gate
  accepted IDs, count, delegation, source agent, and source call must bind the
  contributing agent exactly.

`casepath_release.py verify-runtime-evidence` evaluates that pair without
editing `release.json`, regenerating a source manifest, or changing the tested
commit. It rejects duplicate identities, cache-only evidence, incomplete
roles, failed gates, weak contributions, unreported fallback, missing
usage/cost, tracing, unsafe retained fields, and any release or commit mismatch.

## Render Blueprint

`render.yaml` records the dashboard configuration inspected on 11 August 2026:

| Service | Dashboard ID | Auto-deploy |
|---|---|---|
| `casepath-swiss-claim-lab` | `srv-d9q3ndvavr4c73ao86r0` | commit |

Render associates an existing service by name when a Blueprint is imported.
Before import, inspect the proposed diff and confirm that none of these services
is already managed by another Blueprint. The file contains no deploy hook or
secret. The QA service remains manual so a source-aligned gate is an explicit
release action. The Blueprint pins the API to Python 3.13.9 and QA to Node.js
24.14.1 rather than relying on Render's moving defaults; see Render's
[Python version](https://render.com/docs/python-version) and
[Node.js version](https://render.com/docs/node-version) configuration guidance.
QA dependencies, including Playwright 1.55.0 and `@axe-core/playwright` 4.12.1,
are resolved from `casepath-qa/package-lock.json` with `npm ci` before Chromium
is installed. The canonical QA service explicitly sets
`CASEPATH_ALLOW_PRODUCTION_MUTATION=1` because its reset-and-review journey
mutates only the in-scope evaluation service. That opt-in is required authority
for the hosted gate; it does not enable auto-deploy or expose a deploy hook.
The API configuration also pins the guarded multi-agent runtime profile, keeps
the cumulative application cost ceiling at USD 25, and explicitly disables
LangSmith tracing. `OPENROUTER_API_KEY` remains a secret reference (`sync:
false`) rather than Blueprint content.

## Commands

```bash
python casepath/tools/build_deployment_identity.py --output /tmp/casepath-deployment.json
SOURCE_DATE_EPOCH=1786406400 python casepath-api/generate_artifacts.py
SOURCE_DATE_EPOCH=1786406400 python casepath-api/replace_photographic_evidence.py .
python casepath/tools/casepath_release.py generate
python casepath/tools/casepath_release.py verify
python casepath/tools/casepath_release.py verify-runtime-evidence \
  --report /path/to/qa-output/report.json \
  --evidence-manifest /path/to/qa-output/evidence-manifest.json
```

Before the browser journey starts, production QA must compare the frontend
`deployment.json` with API `/healthz`. `release_id` and a non-`unknown`, 40-hex
`source_commit` must match exactly. The QA report must retain both payloads and
its own `RENDER_GIT_COMMIT`; an unknown or different QA commit is not aligned.

Do not describe a deployment as model-backed unless its same-commit dynamic QA
pair passes the verifier. Do not describe it as expert-reviewed, legally
approved, operationally validated, or suitable for real claims unless those
independent gates have actually been completed with supporting evidence.

## External benchmark archive

The repository contains only the release record and SHA-256 sidecar for
`CasePath_Defects_Expert_Ready_Complete_v1.zip`; it does not copy the external
archive. The original ZIP passes CRC and its internal 2,581-file content
manifest verifies exactly. A recovered clean environment also passes all 1,721
tests. The leakage audit covers 298 reviewer-facing files. However,
`scripts/run_all.py --validate-only --verify-manifest` is not idempotent: the
core verifier expects 2,567 project files, alters a reviewer-preview PNG subset,
and exits 1. Its expected and current counts both remain 2,567, with no missing
or unexpected files, but 195 PNG hash mismatches. The independent comparison
with the 2,581-entry archive content manifest reports the same 195 PNG
mismatches and no missing files. Therefore the original archive is internally
intact, but clean manifest rebuild is a recorded reproducibility blocker rather
than a completed release claim.
